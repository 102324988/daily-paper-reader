## 摘要
大型视觉-语言模型（LVLMs）仍然受限于巨大的计算开销，阻碍了它们在资源受限的边缘设备上的部署。尽管压缩LVLMs的努力主要集中在减少视觉标记或缩小语言模型上，但视觉编码器在很大程度上被忽视，通常作为单体、计算繁重的特征提取器部署。此外，之前没有工作设计直接针对设备端延迟优化的LVLMs视觉编码器。在本文中，我们提出了UltraViT，一种为LVLMs设计的视觉编码器，明确针对设备端性能进行设计和优化。具体而言，通过考虑实际的设备端延迟，我们系统地设计了一个金字塔架构，在宏块级别战略性地集成和调整异构空间混合器。此外，为了预训练UltraViT，我们提出了一种新颖的两阶段生成式预训练策略：通过密集蒸馏培养丰富的空间特征，然后从容量混合的冻结LLM直接进行生成式监督。与标准的对比学习和自监督学习相比，我们表明我们的预训练在实现UltraViT所需的高层语义基础方面更为有效，这对于后续LVLM训练的生成性多模态对齐是必需的。大量实验表明，我们的设备端延迟知情设计结合定制训练策略，为高效LVLM编码建立了新的最先进水平，在设备端以近1.7倍的速度运行，显著优于现有的以编码器为中心的基线。

## Abstract
Large Vision-Language Models (LVLMs) remain bottlenecked by massive computational footprints, precluding their deployment on resource-constrained edge devices. While efforts to compress LVLMs focus heavily on vision token reduction or smaller language models, the vision encoder is largely overlooked, typically deployed as a monolithic, computationally heavy feature extractor. Moreover, there is no previous effort that designs a vision encoder for LVLMs directly optimized for on-device latency. In this paper, we present UltraViT, a vision encoder for LVLMs, explicitly designed and optimized for on-device performance. Specifically, by taking into account real on-device latencies, we systematically design a pyramidal architecture that strategically integrates and adapts heterogeneous spatial mixers at the macro-block level. Furthermore, to pre-train UltraViT, we propose a novel two-stage generative pre-training strategy: cultivating rich spatial features via dense distillation, followed by direct generative supervision from a capacity-mixed frozen LLM. Compared to standard contrastive and SSL, we show that our pre-training is much more effective for achieving high-level semantic grounding for UltraViT needed for the subsequent generative multimodal alignment of LVLM training. Extensive experiments demonstrate that our on-device latency-informed design combined with our tailored training strategy establishes a new state-of-the-art for efficient LVLM encoding, significantly outperforming existing encoder-centric baselines while operating on-device at nearly 1.7xthe speed.

## 1. 核心问题与整体含义

- **研究背景**：大型视觉-语言模型（LVLMs）在多种多模态任务中表现出色，但参数量巨大、计算开销高，难以部署到手机等边缘设备。现有高效 LVLM 压缩工作主要聚焦于两类策略：(1) 通过 token 剪枝/压缩减少视觉上下文长度；(2) 组合更小的语言模型与更高效的跨模态交互机制；**但对视觉编码器本身的延迟优化关注极少**。
- **核心问题**：绝大多数 LVLM 仍依赖 CLIP-ViT-L 或 SigLIP-400M 等重型编码器作为固定特征提取器，其前向推理已成为严重瓶颈。以 LLaVA-OV + Qwen2.5-1.5B 的配置为例，对 1024×1024 输入图像，视觉特征提取阶段可占设备端端到端推理时间的近 50%。随着 LLM 越缩越小，视觉编码器的相对延迟负担越发突出。
- **整体含义**：论文主张 **“从源头设计面向设备端的紧凑视觉编码器”**，而非在部署后再做 token 缩减，为高效 LVLM 边缘部署提供一条视觉编码器维度的新路径。

## 2. 方法论

### 2.1 整体思想
UltraViT 采用经典的四阶段金字塔（pyramidal）拓扑，保留标准 MetaFormer 宏块结构（残差 + 归一化 + TokenMixer + MLP），但**在不同网络阶段策略性地部署不同的空间混合器（heterogeneous mixers）**，并根据真实设备（Galaxy S25 Ultra NPU）上的延迟测量结果来指导混合器选型。

### 2.2 四类空间混合器

- **卷积混合器（Conv Mixer）**：1×1 卷积 + 5×5 深度可分离卷积，用于高分辨率早期阶段以高效捕获局部特征。
- **稀疏混合器（Sparse Mixer）**：基于 EdgeViT 的稀疏注意力改进而来，提出四项核心优化：
  - (S1) 多头→单头
  - (S2) 将稀疏采样算子融合进 Q/K/V 投影（用步长卷积实现）
  - (S3) 用最近邻上采样替代转置深度卷积
  - (S4) 降低注意力投影维度（Q/K 维度 C_qk=16，V 压缩 4 倍）
- **通道分区注意力混合器（CP Attn Mixer）**：借鉴 SH-ViT 的 CPSA，仅对通道子集做单头注意力，其余通道不变，以降低内存访问开销。
- **单头全注意力混合器（Vanilla Attn Mixer）**：用于低分辨率后期阶段，利用全局感受野，用单头替代多头以减少内存碎片。

### 2.3 块选择流程
- 在真实设备上对四种混合器在不同通道数/分辨率下做逐块延迟测量（而非 GPU/CPU 上的 FLOPs 估算），据此确定各阶段最优配置。最终配置为：
  - Stage 1：卷积混合器
  - Stage 2：卷积 + 稀疏混合器交错
  - Stage 3：通道分区注意力
  - Stage 4：单头全注意力
- 另配备 stem（4× 下采样）、跨阶段下采样块（1×1 卷积 + 3×3 步长 DW 卷积 + SE 模块）和多尺度特征聚合器。

### 2.4 两阶段生成式预训练策略

**阶段 1：密集蒸馏（Dense Distillation）**
- 教师模型：SigLIP2-B16 NaFlex；大教师设为 SigLIP2-400M。
- 学生与教师特征空间分辨率不匹配时，用 **Pixel Shuffle** 将学生 token 重排到教师分辨率；无法对齐时对教师特征做对齐降采样。
- 损失 = 0.5·L_dense（逐 patch 余弦相似度）+ 0.5·L_global（经教师注意力池化后的全局余弦相似度）。

**阶段 2：生成式预训练（Generative Pre-training）**
- 将密集蒸馏后的编码器接入**冻结的、已与视觉对齐的 LLM**（Qwen2，0.5B 和 1.5B）作为解码器，进行自回归下一 token 预测。
- 核心动机：强冻结 LLM 可卸载语言建模负担，使视觉编码器专攻视觉特征；并且对比现有 GIT、CapPa 等方法用小解码器导致视觉编码器被迫承担语言建模的问题。
- 提出 **动态容量混合策略**：在 0.5B 与 1.5B LLM 间动态切换，兼顾语义对齐质量与预训练开销。

## 6. 主要结论与发现

- **UltraViT 显著优于 FastVLM**：在 TextVQA（+6.0%）、DocVQA（+5.1%）、ChartQA（+6.2%）等细粒度推理任务上大幅领先，同时视觉编码器推理速度约为 FastVLM 的 **1.7 倍**。
- **原生 token 缩减**：金字塔架构天然输出 16 倍更少的视觉 token，同时视觉编码器本身比 SigLIP-400M 快 **19.1 倍**，在 LLM 侧也节约了相应计算量。
- **两阶段预训练策略有效**：密集蒸馏优于对比学习（SigLIP），加生成式预训练进一步提升；动态 LLM 混合策略以更低的训练成本达到接近纯 1.5B 模型的效果。
- **预训练效率高**：相比 FastVLM 的 2B 图像/13B 样本，UltraViT 仅用约 1/10 的唯一图像（235M）和约 1/3 的样本量（4.1B），即取得更优结果。
- **鲁棒性强**：对教师模型选择不敏感；在 GPU/CPU 上同样优于 FastViT；在 256~1536 全分辨率范围内保持速度优势。

## 7. 优点

- **填补空白**：首次针对 LVLM 场景、以真实设备端延迟为导向设计视觉编码器，拓展了高效 LVLM 的优化维度。
- **硬件导向的异构架构**：不盲目重复同一空间混合器，而是基于 NPU 实测延迟数据做逐阶段混合器选型，思想清晰且可复现。
- **预训练与 LVLM 需求对齐**：密集蒸馏保证空间细节，LLM-in-the-loop 生成式监督提供高层语义，避免了 CLIP 与生成式 LVLM 使用之间“最后一层必须丢弃”的对齐错位。
- **数据效率突出**：极少的预训练数据即可超过用 13B 样本训练的 FastVLM。
- **显式防御 token 缩减方法固有缺点**：内部 token 缩减不牺牲精度、不增加额外计算，架构原生实现即优于后处理剪枝。
- 实验覆盖了设备端/NPU/GPU/CPU、多分辨率、多基准、多消融，完整度较高。

## 8. 不足与局限

- **以单一设备生态为基础的设计**：延迟选型基于 Galaxy S25 Ultra（Qualcomm NPU）+ INT8 QNN 编译，结论对其他平台（Apple Neural Engine、Mali GPU、低端 NPU）的可迁移性未验证，存在硬件偏向风险。
- **参数量与 FLOPs 仍偏大**：UltraViT 参数约 139.4M、FLOPs 约 143.9B（512×512），尽管速度快，但仍非严格意义的小模型。
- **只在单一 LVLM 框架中验证**：主实验均基于 LLaVA-OV + Qwen2.5-1.5B，未与其他 LLM 主干（如 3B/7B）或其他项目架构（如 MobileVLM、SmolVLM 流程）集成验证。
- **部分对比公平性受限**：与 QwenVL 系列对比时，在 token 受限设定下比较虽然公平但仍是“以小博大”；原始 FastVLM 结果数据量更大（16.1M vs 7.1M 微调样本），只做参考。
- **生成式预训练对 LLM 依赖度未知**：对“已对齐”的冻结 LLM 依赖较强，若 LLM 对齐质量或容量不同，效果如何变化未充分讨论。
