## 摘要
边缘部署的视觉系统在目标识别、监控、自动驾驶和无人机领域需要分层推理流水线，其中检测模型识别感兴趣的目标，下游分类器提供细粒度的属性分析。在GPU上运行所有模型会产生串行瓶颈，随着流水线阶段的增加，限制了实时吞吐量。现代边缘SoC将GPU与专用的神经加速器（NPU、DLA）配对，能够并发执行，但由于严格的操作符约束、量化不兼容和未记录的端到端流水线，在这些加速器上部署自定义模型仍然不切实际。我们以NVIDIA Jetson DLA核心作为代表性平台。我们提出了一种五步方法论，用于分类主干的零GPU回退DLA INT8部署，包括架构适配、手动动态范围变通方案以拯救TensorRT的隐式量化（从隐式量化的75%恢复94.0%的准确率）以便在显式量化前快速验证流水线、量化感知训练、用于DLA编译的ONNX图手术，以及并发的GPU检测/DLA分类推理流水线。我们记录了九个工程约束及其根本原因分析和通用解决方案。在Jetson Orin NX上，双头人物属性分类器与GPU目标检测器同时在DLA上运行的验证表明，流水线开销接近零（1080p下仅检测器为12.5 vs 13.3 FPS），双DLA扩展无额外成本。该方法论与主干无关，适用于任何检测-分类边缘流水线。

## Abstract
Edge-deployed vision systems in target recognition, surveillance, autonomous vehicles, and drone domains require hierarchical inference pipelines where a detection model identifies objects of interest and downstream classifiers provide fine-grained attribute analysis. Running all models on the GPU creates a serial bottleneck that limits real-time throughput as pipeline stages grow. Modern edge SoCs pair GPUs with dedicated neural accelerators (NPUs, DLAs) capable of concurrent execution, yet deploying custom models on these accelerators remains impractical due to strict operator constraints, quantization incompatibilities, and an undocumented end-to-end pipeline. We target NVIDIA Jetson DLA cores as the representative platform. We present a five-step methodology for zero GPU fallback DLA INT8 deployment of classification backbones, comprising architecture adaptation, manual dynamic range workaround to rescue TensorRT's implicit quantization (recovering 94.0% accuracy from implicit quantization's 75%) for rapid pipeline validation before explicit quantization, quantization-aware training, ONNX graph surgery for DLA compilation, and a concurrent GPU-detection/DLA-classification inference pipeline. We document nine engineering constraints with root-cause analysis and generalizable solutions. Validation on a dual-head person attribute classifier running on DLA alongside a GPU object detector on a Jetson Orin NX demonstrates near-zero pipeline overhead (12.5 vs. 13.3~FPS detector-only at 1080p), with dual-DLA scaling at no additional cost. The methodology is backbone-agnostic and generalizes to any detection-classification edge pipeline.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- 边缘部署的视觉系统（目标识别、监控、自动驾驶、无人机）通常采用分层推理流水线：先由检测模型识别目标，再由一个或多个下游分类器执行细粒度属性分析（人员类型、姿态、车辆颜色/型号、是否携带装备等）。
- 传统做法将所有模型都放在 GPU 上运行，导致硬件资源共享、流水线串行化，实时吞吐能力随分类器数量的增加而急剧下降。
- NVIDIA Jetson 系列 SoC 同时拥有 GPU 与 1–2 个专用深度学习加速器（DLA）核心。以 Jetson Orin NX 为例，总算力 100 TOPS 中 GPU 占 60 TOPS，两个 DLA 核心共占 40 TOPS（2×20），但在典型应用中 DLA 完全闲置，意味着约 40% 的芯片算力未被利用。
- 将分类器从 GPU 卸载到 DLA 可实现真正的硬件级并行：GPU 处理当前帧检测，DLA 同时分类上一帧的目标裁切块，理论上分类近乎“零开销”。
- 然而，在 DLA 上部署自定义模型面临严重工程障碍：DLA 算子支持受限（拒绝 Flatten、Linear/Gemm、AdaptiveAvgPool、某些维度的 Concat 等）、TensorRT 隐式 INT8 量化已弃用、显式 Q/DQ 量化节点 DLA 无法直接执行、熵校准在 DLA 上严重精度退化等，且缺少完整、经过实验验证的部署流程文档。
- 论文针对以上缺口，提出并验证了一套系统的五步方法论，并公开了 9 个工程约束的根本原因与通用解决方案。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

**核心思想**：将分类网络改造为 DLA 原生算子可执行的 INT8 量化模型，通过显式 Q/DQ 节点 + 自定义 ONNX 图手术生成 DLA 引擎；再通过帧 N−1 异步流水线，使 GPU 检测与 DLA 分类并行，实现分类对检测路径的近零开销叠加。

**五步方法论**：

1. **Step 1：DLA 安全架构适配（DLA-Safe Architecture Adaptation）**
   - `nn.Linear(C, num_classes)` → `Conv2d(C, num_classes, kernel_size=1)`，数学等价且导出为 DLA 原生 Conv。
   - `AdaptiveAvgPool2d(1)` → `AvgPool2d(kernel_size=7)`（显式核大小，DLA 仅支持 ≤8 窗口）。
   - 多分类头输出不再使用 `torch.cat`（会导致 DLA 编译器崩溃），而是将 K 个头的权重按输出通道拼接，融合为单个 `Conv2d(C→K, 1×1)`，等效且单算子执行。
   - 激活函数推荐 ReLU6（有界输出 [0,6] 利于手动动态范围推导）；标准 ReLU 也可用，但精度略低。
   - 全程保持 4D 张量格式，无 Flatten/Reshape。

2. **Step 2：显式量化，实现每层 Q/DQ 全覆盖**
   - 使用 TensorRT 的 pytorch-quantization 库，将每个 Conv2d 替换为 QuantConv2d（自动插入输入/权重 Q/DQ）。
   - 每个 BasicBlock 残差分支必须添加 `skip_connection_quantizer`，否则残差 Add 节点缺少 INT8 尺度，会触发 FP16 或 GPU 回退（C4 约束）。
   - 在非卷积边界添加显式量化器：`post_backbone_quantizer`（layer4 输出之后、AvgPool 之前）和 `post_head_quantizer`（head 卷积输出之后、Sigmoid 之前）。
   - 移除 Sigmoid 之后的量化器：Sigmoid 输出 [0,1] 近似均匀分布，熵校准产生退化 amax（除零）；且输出仅 32 个元素，INT8 vs FP16 无差异（C6 约束）。

3. **Step 3：INT8 量化策略**
   - **PTQ 熵校准失败**：TensorRT 隐式 ENTROPY_CALIBRATION_2 在 DLA 上产生严重精度退化（ReLU6 模型 75%，标准 ReLU 低至 66–69%）。
   - **手动动态范围修复（快速验证路径）**：结构性地设置动态范围——输入 [−4,4]，中间层 [−8,8]（由 ReLU6 上界+残差余量导出），输出 [−1,1]（head 卷积 logit 范围）。在 PTQ 模型上直接应用可恢复 94.0% 准确率，免训练、数分钟完成，可用于流水线验证。
   - **QAT（生产路径）**：从 FP32 检查点微调，使用直通分布校准。支持三种 amax 计算方法：熵、MSE、百分位（99.99th），论文选择百分位作为推荐，因其保留 ReLU6 密集激活范围、丢弃残差加法产生的瞬态尖峰。

4. **Step 4：ONNX 导出与 DLA 编译**
   - 导出后先运行 `onnxsim.simplify()`，移除 Cast/Identity 等无操作节点，否则图遍历脚本失败（C9）。
   - 自定义图手术脚本（graph surgery）：遍历 ONNX 图，提取每个 Q/DQ 对中的逐张量 INT8 尺度；通过 pass-through 算子（ReLU6、AveragePool）传播尺度；剥离所有 Q/DQ 节点；生成干净的 ONNX 模型与 TensorRT calibration cache。
   - TensorRT Python API 构建 DLA engine：INT8、DLA core 指定、允许 GPU fallback 但最终校验为零 fallback 层。

5. **Step 5：异步并行流水线集成（帧 N−1）**
   - 为 GPU 检测和每个 DLA 引擎分配独立 CUDA stream。
   - 帧处理流程：同步 DLA stream 取回上一帧分类结果 → GPU 检测 + 在 GPU 上完成 crop 提取/letterbox/resize/归一化 → 非阻塞式将预处理张量复制到 DLA 输入并调用 `execute_async_v3` 入队 → CPU 立即处理下一帧。
   - 分类结果滞后一帧，实时视频场景可接受。
   - DLA 引擎要求固定 batch size（本文为 16），检测数不足时零填充，同步后丢弃填充输出。
   - 双 DLA 扩展：第二个分类器在 DLA core 1 上独立实例化，通过 CUDA event 在预处理后触发，两个 DLA 引擎并发执行互不干扰。

## 6. 论文的主要结论与发现

- 提出的五步方法论可在 DLA 上实现零 GPU 回退的自定义 INT8 分类器部署，骨干无关、检测器无关。
- PTQ 熵校正在 DLA 上会严重失效（75% 甚至 66–69%），而结构化手动动态范围可将精度恢复到 94.0%，接近 QAT 水平（95.0%），且几乎零成本。
- QAT + 99.99th 百分位校准 + 显式 Q/DQ 图手术可达到与 FP32 基线相等甚至更优的精度（95.0% vs 94.5%），ROC-AUC 差异在 0.002–0.005 以内。
- 帧 N−1 异步并行使 DLA 分类对检测路径的吞吐影响近乎为零：1080p 下 YOLO-only 13.3 FPS，YOLO+DLA 分类 12.5 FPS，开销约 6%；720p 下 27.5 vs 25.0 FPS，开销约 9%。该开销完全来自 GPU 端 crop 预处理，而非 DLA 执行。
- 双 DLA 并行与单 DLA 并行吞吐完全一致（12.5/25.0 FPS），证明 DLA 核心间独立、互不干扰；而增加第二个 GPU 分类器会进一步加重串行吞吐损失（1080p 下 9.6 FPS）。
- 经典观点“组件更快的 GPU 分类器”反而导致更差的流水线吞吐——说明共享硬件上组件延迟不是关键指标，DLA 的硬件隔离才是近零开销的根源。
