## 摘要
视觉Transformer（ViT）在一系列计算机视觉任务中取得了最先进的性能，这主要归功于自注意力机制。然而，其复杂度随token数量呈二次增长，仍是ViT效率和规模化部署的主要障碍。Token合并通过聚合冗余token来降低这一开销。然而，现有方法通常仅在单一架构内进行评估，因此尚不清楚其有效性是源于合并机制本身，还是源于与之配对的特定解码器。我们将图引导Token合并（Graph-Guided Token Merging, G2TM）——一种插入基于ViT网络早期阶段的单一模块——从最初的Segmenter设置扩展到更广范围。我们在三个语义分割框架（Segmenter、SETR、EoMT）和三类解码器（线性、基于Transformer、基于卷积）以及标准ViT图像分类上评估G2TM。结果表明，在给定骨干网络规模下，G2TM的行为以及精度-效率权衡在所有测试架构中保持一致，这表明其有效性是编码器的属性，而非解码器的属性。G2TM在图像分类上也具有良好的泛化能力，与语义分割相比，其精度下降甚至更小。我们进一步发现，对于ADE20K数据集上的分割模型，G2TM的最优超参数可使GFLOPs稳定下降22–47%、吞吐量最高提升74%，而这些超参数主要取决于骨干网络的预训练方案和目标数据集，而非解码器的选择。

## Abstract
Vision Transformers (ViTs) have achieved state-of-the-art performance across a range of computer vision tasks, mainly thanks to the self-attention mechanism. However, its complexity, increasing quadratically with the number of tokens, remains the major obstacle to ViT efficiency and deployment at scale. Token merging reduces this cost by aggregating redundant tokens. Yet existing methods are typically evaluated within a single architecture, leaving open whether their effectiveness stems from the merging mechanism itself or from the specific decoder they are paired with. We extend Graph-Guided Token Merging (G2TM), a single module inserted early in a ViT-based network, beyond its original Segmenter setting. We evaluate G2TM across three semantic segmentation frameworks (Segmenter, SETR, EoMT) and three decoder families (Linear, Transformer-, convolution-based), as well as standard ViT image classification. Our results show that G2TM's behavior and accuracy-efficiency trade-off are consistent across every tested architecture for a given backbone size, indicating that its effectiveness is a property of the encoder rather than the decoder. G2TM also generalizes well to image classification, achieving an even smaller degradation in accuracy compared to semantic segmentation. We further find that G2TM's optimal hyperparameters, resulting in a consistent drop in GFLOPs of 22-47% and an increase in throughput by up to 74% for segmentation models on ADE20K dataset, depend primarily on the backbone's pre-training recipe and on the target dataset, rather than on the decoder choice.

# 论文总结：面向视觉 Transformer 的解码器无关 Token 合并（G2TM 的系统性研究）

## 1. 核心问题与整体含义

- **背景**：Vision Transformer（ViT）凭借自注意力机制在计算机视觉任务中达到 SOTA，但自注意力复杂度随 token 数量**二次增长**。语义分割等密集预测任务需要高分辨率输入，token 数常超过一千，成为 ViT 效率与规模化部署的主要瓶颈。
- **已有方案**：Token 合并（token merging）通过聚合冗余 token 缩短序列长度，是降低开销的有效手段；相关工作如 ToMe、ALGM、PiToMe、ATC、AiluRus、GTP-ViT 等。
- **核心问题**：现有 token 合并方法**通常只在单一模型架构内评测**，因此无法判断其有效性究竟来自**合并机制本身**，还是来自与之配对的**特定下游解码器**。这在解码器差异巨大的语义分割领域尤为突出（线性、卷积、Transformer 三类解码器计算量从 0.16 GFLOPs 到 90.82 GFLOPs 不等）。
- **整体含义**：本文把已有的 **G2TM（Graph-Guided Token Merging）** 从最初的 Segmenter 设置扩展到多个分割框架、多类解码器以及图像分类任务，系统回答“G2TM 的有效性是编码器属性还是解码器属性”，并给出可操作的调参指南。

## 2. 方法论

### 2.1 核心思想
- G2TM 是**单一插入式模块**，只放入 ViT 编码器的**某个浅层 Transformer block**（通常是第 1 或第 2 层）中，位于注意力层与残差连接之后。
- 将 token 序列建模为**图**，用图论中的连通分量来定义“可合并的冗余 token 组”，仅在**空间相邻且语义相似**的 token 之间进行融合。
- 采用**动态合并**：合并的粒度随输入图像和 token 语义自动调整，不固定删除 token 数量。

### 2.2 关键技术细节与算法流程
1. **图构建**：构建无向图 G=(V,E,W)。
   - 顶点 V = 当前 token 序列 T_i^ATTN；
   - 边 E 连接空间相邻 token（图像网格 4 邻域，仅计算右邻与下邻以避免冗余）；
   - 边权 W 为 token 嵌入之间的余弦相似度：cs_{i,j} = t_i·t_j / max(‖t_i‖‖t_j‖, ε)，ε≈10⁻⁸ 保证数值稳定。
2. **动态边切割**：预先设定阈值 τ，删除相似度低于 τ 的边，将图分割为若干**连通分量** {C₁,…,C_K}，每个分量代表一组局部相似的 token。
3. **分量检索**：用**广度优先搜索（BFS）**找出所有规模大于 1 的连通分量，并记录其 token 索引，供后续 unmerging 使用。
4. **Token 融合**：对每个连通分量做**无权重平均**，得到代表 token t̄_j；原始 token 被移除并由该代表 token 替代，输出序列长度 N′≤N。
5. **训练策略（掩码自注意力）**：
   - 训练时 batch 内序列长度必须一致，因此**不真正缩短序列**，而是保留原长度，用**掩码自注意力**屏蔽分量内除代表 token 外的所有 token；
   - 训练结束后（所有 Transformer block 之后）执行 **unmerging**：把代表 token 的嵌入复制回其分量内所有原始位置，再送入决策层。
6. **推理策略**：直接删除分量内 token 并替换为平均代表 token，实现真实的序列缩短、显存与计算节省。
7. **Unmerging 与解码器适配**：
   - 卷积 / 线性解码器需要稠密空间表示 → 在解码器前进行 unmerging（Option 2）；
   - Transformer 解码器可直接处理稀疏 token 序列 → 可延后甚至省略显式恢复（Option 1）。
8. **阈值课程（curriculum）**：训练开始时用较高 τ，每个阶段降低 0.01，逐步让网络适应 token 缩减，提高训练稳定性（记为 G2TM †）。

## 6. 主要结论与发现

1. **解码器无关性**：在给定骨干规模下，G2TM 的合并行为（剩余 token 数、平均合并大小）和精度-效率权衡在**所有测试架构中高度一致**，说明其有效性是**编码器的属性**，而非解码器的属性。
2. **精度-效率收益**：ADE20K 上，在 mIoU 损失不超过 2 点的前提下，**GFLOPs 稳定下降 22%–47%，吞吐量最高提升 74%**；Cityscapes 上吞吐量最高提升 **94%**。
3. **分类泛化更好**：ImageNet-1k 上 Top-1 最多仅下降 **0.7 点**，GFLOPs 下降 22%–35%，说明分类对 patch token 合并的容忍度高于分割。
4. **超参数主导因素**：最优 τ 与插入层主要取决于**骨干预训练方案**和**目标数据集**，而**与解码器选择和图像分辨率无关**（同一数据集内换分辨率无需重调）。
5. **骨干规模影响合并位置**：ViT-T/S/B 偏好第 2 层合并（G2TM †@2），而 **ViT-L 在第 1 层合并更优**，原因是更大更宽的 Transformer 更快同质化 token 表示（余弦相似度分布更集中于高分）。
6. **预训练影响显著**：DINOv2 预训练使相似度几乎全部落在 0.99–1.0，导致阈值失去判别力，EoMT-DINOv2 上 mIoU 下降高达 **8.8 点**；而 AugReg 预训练下 EoMT 几乎无损（<0.3 点）。
7. **PA 应任务条件化**：Proportional Attention 对分类略有增益，但在分割上**一致有害**，建议分类启用、密集预测禁用。
8. **吞吐量阈值效应**：当原模型吞吐量低于约 **100 FPS** 时 G2TM 有效；高于该阈值（如 ViT-T/S）时，合并自身的开销无法被注意力节省抵消，吞吐量反而下降。

## 7. 优点

- **研究视角新颖**：把“token 合并方法的收益归因”作为研究问题，明确区分编码器属性与解码器属性，具有方法论价值。
- **评测系统性强**：跨 3 个分割框架、3 类解码器、4 种骨干规模、2 个任务、2 个数据集、2 种分辨率，覆盖维度完整。
- **提供可操作指南**：明确指出调参应依据预训练方案与数据集、而非解码器；给出用**余弦相似度分布**快速判断合并层与阈值的实用方法。
- **训练/推理机制设计巧妙**：训练时用掩码自注意力保持 batch 长度一致，推理时真正缩短序列，兼顾训练效率与部署加速。
- **对失败情形的诚实分析**：如 DINOv2 预训练下的性能崩塌、轻量模型上的吞吐量反降、PA 在分割上的负面作用，均给出了机理解释。

## 8. 不足与局限

- **方法自身限制**：
  - 阈值 τ 需**人工按数据集/预训练方案重新调参**，缺乏自适应或可学习机制；
  - 仅与自身基线对比，**未与 ToMe、ALGM、PiToMe 等主流 token 合并方法进行定量横向对比**，相对优势不明确；
  - 合并策略基于固定的 4 邻域空间图，对非网格结构或高度非局部冗余的适应性有限。
- **实验覆盖局限**：
  - 仅涉及语义分割与图像分类，**未验证目标检测、实例分割、深度估计等其他密集预测任务**；
  - 分辨率实验仅在 Cityscapes 上做，**未在 ADE20K 上验证分辨率的无关性**；
  - EoMT 本身无显式解码器，被作者“人为视作解码器”处理，边界定义存在一定模糊性。
- **算力披露不足**：未报告训练 GPU 数量与时长，难以评估训练成本与可复现性；ViT-L 分类训练 batch size 被下调，可能与原论文结果不完全可比。
- **偏差风险**：所有分割模型统一使用 AugReg 预训练权重（与 SETR/EoMT 原论文不同），虽然增强了内部一致性，但可能使结论**偏离各框架的最优配置**，影响对外部基线的可比性。
- **应用限制**：在吞吐量高于约 100 FPS 的轻量模型上无法带来实际加速，部署收益高度依赖原始模型的计算规模。
